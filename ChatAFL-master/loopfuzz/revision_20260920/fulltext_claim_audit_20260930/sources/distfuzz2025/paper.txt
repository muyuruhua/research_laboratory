Fig. 3: A bug in RethinkDB [47] that makes a newly created databases unusable. This bug is triggered by the following sequences
of regular events. First, the client sends CreateDB("db1") requests to Node A and B at almost the same time. Node A creates the
database with the name "db1" and sends Node B a message to announce the creation. However, before receiving the message,
Node B has already created the database with the name "db1". As a result, any request involving access "db1" will fail, since the
servers found that there are two databases with the same name "db1". So, the Put request to "db1" will fail and causes DistFuzz
detecting the bug. The fix is to synchronize the database creation among nodes with consensus protocols.
