================================================================================
一、ChatAFL 基线完整工作流
================================================================================

1.1 启动流程（main函数，afl-fuzz.c L10233起）
──────────────────────────────────────────────

  命令行解析 → 共享内存/fork server初始化 → IPSM图创建
  → setup_llm_grammars()（同步阻塞）
  → enrich_testcases()（同步阻塞，串行）
  → read_testcases()
  → perform_dry_run()
  → 主fuzz循环 while(1)

1.2 setup_llm_grammars() — 启动期LLM语法抽取（chat-llm.c）
──────────────────────────────────────────────────────────

  1. construct_prompt_for_templates(protocol_name, &final_msg)
  2. 对同一提示词执行 TEMPLATE_CONSISTENCY_COUNT=5 次迭代
  3. 每次迭代调用 chat_with_llm() 两次（temperature=0.5）：
     - 第1次：获取主要消息类型模板 → construct_prompt_for_templates()
     - 第2次：补充剩余模板 → construct_prompt_for_remaining_templates()
  4. 共10次LLM调用（5×2），结果通过一致性投票合并
  5. 输出到全局变量：protocol_patterns (klist_t(rang)), message_types_set (khash_t(strSet))
  关键常量：GRAMMAR_RETRIES=5, MESSAGE_TYPE_RETRIES=5, MAX_TOKENS=2048
  API配置：url=lingyunapi.com, model=gpt-4o/gpt-4o-mini
  线程安全：无（主线程单线程，全局变量curl_global_init/cleanup每次调用）

1.3 enrich_testcases() — 启动期种子充实（afl-fuzz.c L2796）
───────────────────────────────────────────────────────────

  1. get_seeds_with_messsage_types(in_dir, message_types_set)
  2. 遍历每个种子×缺失消息类型组合，串行调用 enrich_sequence()
  3. enrich_sequence() → chat_with_llm(temperature=0.5) → extract_stalled_message()
  4. 写入 enriched_N_filename 文件
  执行方式：串行、阻塞、无超时、无并发

1.4 主循环状态评分（afl-fuzz.c L828附近）
─────────────────────────────────────────

  update_scores_and_select_next_state(FAVOR):
    state->score = ceil(1000 × 2^(-log₁₀(log₁₀(fuzzs+1)×selected_times+1))
                          × 2^(ln(paths_discovered+1)))
  仅基于三个计数器（fuzzs, selected_times, paths_discovered）
  不感知IPSM图拓扑（出度=0与出度=10无区别）
  无error_hint, 无productivity跟踪
  前5轮(state_cycles<5)使用ROUND_ROBIN

1.5 send_over_network() — 网络执行（aflnet.c）
───────────────────────────────────────────────

  单连接路径：所有协议共用一个fd
  两个真正的while(1)无界循环：
    - 覆盖率稳定循环：while(1) { if (has_new_bits(session_virgin_bits) != 2) break; }
    - 进程终止等待：SIGTERM后while(1)等待，永不发送SIGKILL
  MQTT请求解析：简单mem[1]作为长度（不支持变长Remaining Length编码）
  MQTT响应解析：硬编码10种首字节匹配（0x20/0x40/0x50/...），不包含PUBLISH转发

1.6 运行时LLM停滞处理（afl-fuzz.c L6851起）
────────────────────────────────────────────

  触发：uninteresting_times >= UNINTERESTING_THRESHOLD(512) && chat_times < 64
  流程：
    1. 读取responses-ipsm/响应历史文件
    2. construct_prompt_stall() — 固定文本模板，不含IPSM拓扑信息
    3. 主进程内同步调用chat_with_llm(prompt, "gpt-4o-mini", STALL_RETRIES=2, temperature=1.5)
       — 无fork隔离，无超时保护，主循环完全暂停
    4. extract_stalled_message() 正则提取
    5. common_fuzz_stuff() 执行 → chat_times++
  本质：开环单向翻译器。LLM建议效果无反馈通道。

1.7 关键常量
─────────────
  UNINTERESTING_THRESHOLD = 512 (config.h L76)
  CHATTING_THRESHOLD = 64
  STALL_RETRIES = 2
  GRAMMAR_RETRIES = 5
  MAX_TOKENS = 2048
  TEMPLATE_CONSISTENCY_COUNT = 5
  API endpoint: lingyunapi.com, 模型: gpt-4o / gpt-4o-mini

4.1 ChatAFL基线 — 开环控制
────────────────────────────
  启动期LLM（一次性）→ 协议知识固化 → 永不再更新
  运行时：固定阈值512 → 固定文本模板（无IPSM拓扑信息）
          → 主进程同步阻塞LLM → 正则提取 → 加入队列
  LLM建议效果 ↛ 无反馈通道

4.2 ChatAFL-Opt — 自适应闭环控制
───────────────────────────────────
  三个可观测量驱动四个执行器：

  可观测量：
    O₁ = IPSM边增长率 Ė = d(agnedges)/dt  (L11100-11106)
    O₂ = 每状态productivity = paths_discovered/(selected_times+1)  (aflnet.h L35)
    O₃ = Hypothesis fitness = 0.7×parse_rate + 0.3×avg_constraint_confidence  (grammar-hypothesis.c L2292)

  执行器：
    E₁ = LLM介入阈值 τ(Ė) — 自适应plateau (L11108-11137)
    E₂ = 状态选择权重 β(deg⁺, error_hint, productivity) — frontier scoring (L2550-2590)
    E₃ = LLM操作指令 actions[] — set_target_state/prioritize_seeds/propose_mutations (L11572-11850)
    E₄ = Hypothesis精炼 — Tier-2 LLM refinement (L11163-11165)

  反馈回路：
    Ė↑→τ↑  Ė↓→τ↓  deg⁺↓→β↑  error_hint=1+prod↓→β×0.5
    error_hint=1+prod↑→提升为2  fitness↓+counterexamples↑→触发精炼

六、一句话总评
================================================================================

ChatAFL是"开环的LLM辅助模糊测试器"——启动期一次性LLM批处理后，运行时LLM通道完全开环。

ChatAFL-Opt已升级为"状态感知+反例反馈+调度自适应+MQTT专项增强"的闭环协议模糊测试系统。
