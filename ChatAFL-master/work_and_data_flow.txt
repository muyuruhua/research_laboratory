ChatAFL（基线）与 ChatAFL-Opt 的工作流、本质与底层逻辑
一、ChatAFL 基线的完整工作流
第一阶段：初始化与启动时文法充实

程序启动后，主函数依次完成命令行参数解析、共享内存和 fork server 的初始化、IPSM（推断协议状态机）的创建。若检测到 `-P` 协议参数（protocol_selected），立即进入两阶段阻塞式 LLM 充实流程，之后才调用 read_testcases() 开始读取初始种子。

第一小阶段是文法模板获取（setup_llm_grammars()）：对同一组提示词重复发起 TEMPLATE_CONSISTENCY_COUNT=5 次迭代，每次迭代包含两次 chat_with_llm 调用（temperature=0.5，model=gpt-4o-mini）——一次获取主要消息类型模板，一次补充剩余模板——共 10 次 LLM 调用。各次迭代的结果通过一致性投票合并，只保留在多数迭代中都出现的字段，生成 protocol_patterns 语法规则和 message_types_set 消息类型集合。

第二小阶段是种子充实（enrich_testcases()）：遍历 in_dir 中的每个初始种子文件，检查其中缺少哪些已知消息类型，对每个"缺失组合"调用一次 enrich_sequence()（内部调用 chat_with_llm，temperature=0.5），要求 LLM 在现有请求序列中插入缺少的消息类型，生成新的 enriched_N_filename 种子文件写回 in_dir。整个过程串行、阻塞，若初始种子多且缺失的消息类型组合多，LLM 调用数量可以很大。config.h 中定义的两个运行时常量：UNINTERESTING_THRESHOLD=512（停滞触发阈值），CHATTING_THRESHOLD=64（LLM 调用总次数上限）。

第二阶段：种子选择与状态评分

初始化完成后进入主循环。每一轮首先调用 choose_target_state(FAVOR) 选出目标状态：通过 update_scores_and_select_next_state(FAVOR) 对所有已知状态计算得分并做加权随机抽取。得分公式为：score = ceil(1000 × 2^(-log₁₀(log₁₀(fuzzs+1) × selected_times + 1)) × 2^(ln(paths_discovered+1)))。第一个指数因子为负，fuzzs（变异次数）和 selected_times（被选次数）越大得分越低；第二个因子用自然对数，paths_discovered（已发现的新路径数）越大得分越高。综合效果是：探索不足但已有发现潜力的状态优先，但这个公式完全不感知 IPSM 图的拓扑结构——一个出度为 0 的边界节点和一个出度为 10 的中心节点，在 fuzzs、selected_times、paths_discovered 相同时获得完全相同的调度优先级。选定目标状态后，通过 choose_seed(target_state_id, mode) 从该状态的种子池中选出具体种子。

第三阶段：变异与执行

选定种子后，对其进行比特翻转、算术运算、字典替换、拼接等标准 AFL 变异操作，再通过 send_over_network() 发送给目标服务器并采集覆盖率与状态转移。

send_over_network() 的末尾有两个 while(1) 循环，均无上限。第一个循环在发送完所有数据包后反复调用 has_new_bits(session_virgin_bits)，只要覆盖率位图仍有新位就继续等待——对于 forking daemon（如 pure-ftpd），子进程的 ASAN 析构、fd 清理等收尾操作持续产生新覆盖位，导致此循环长时间自旋。第二个循环在网络交互结束后向 child_pid 发送 SIGTERM（仅当 terminate_child 标志置位时），然后反复检查 kill(child_pid, 0) 直到进程消失——若进程不响应 SIGTERM，此循环将永远自旋，整个主循环无法推进。send_over_network() 从不发送 SIGKILL；SIGKILL 只由 AFL 的 SIGALRM 超时处理器在 child_timed_out 时发出，在 run_target() 中被正确识别为 FAULT_TMOUT。

第四阶段：停滞检测与 LLM 介入

uninteresting_times 是一个全局计数器，在每次 common_fuzz_stuff() 执行后更新：若 save_if_interesting() 返回真（发现新路径或新状态），重置为 0；否则递增。当 uninteresting_times >= 512 且 chat_times < 64 时，重置 uninteresting_times=0 并触发 LLM 对话。

触发后的完整流程：读取当前种子的历史响应文件（responses-ipsm/id:...），将最近的请求-响应对拼接成 history 字符串，将首两条请求格式化为 examples，调用 construct_prompt_stall(protocol_name, examples, history) 生成纯文本提示词（大意为"当前 X 协议的测试停滞了，已观察到以下交互，请建议下一条可能有效的消息序列"），提示词中不包含任何 IPSM 拓扑信息。然后在主进程内直接调用 chat_with_llm(prompt, "gpt-4o-mini", 2, 1.5)——temperature=1.5 以增加多样性，重试次数上限 2。整个 HTTP 请求在主进程内同步等待，主循环完全暂停。返回的自由文本响应通过 extract_stalled_message() 用正则匹配提取消息序列，格式化后通过 common_fuzz_stuff() 执行，chat_times 递增。提示词和响应分别保存到 stall-interactions/prompt-N 和 stall-interactions/response-N。

本质总结：

ChatAFL 的 LLM 集成本质上是"一次性启动充实 + 定时触发的盲猜翻译器"。启动时两阶段阻塞式 LLM 调用（文法获取+种子充实）固化了协议知识，此后不再更新；运行时以固定阈值 512 触发、固定模板提示、主进程同步阻塞等待、正则解析自由文本的方式获取 LLM 建议。LLM 在停滞触发时对 IPSM 的当前拓扑一无所知——不知道有多少状态、哪些状态是边界、哪些状态从未被探索。用控制论的术语说，这是一个开环控制器：LLM 输出不依赖于模糊测试器的实际运行状态，也没有任何机制将 LLM 建议的效果反馈到下一次的提问策略中。

二、ChatAFL-Opt 的完整工作流
第一阶段：初始化（延迟加载 + 并行启动充实）

程序启动时，同样完成参数解析、共享内存、fork server 和 IPSM 的初始化，之后在 protocol_selected 分支中进行与基线相同结构的两阶段 LLM 充实。不同之处在于：

文法模板获取（setup_llm_grammars()）与基线相同——5 次迭代 × 2 次 LLM 调用，串行阻塞。

种子充实（enrich_testcases()）使用 pthread 线程池替代串行循环：先收集所有种子×消息类型组合的充实任务，然后以 ENRICHMENT_THREADS=32 个工作线程并发执行所有 enrich_sequence() 调用，主线程以 pthread_join 等待所有线程完成后统一写入结果种子文件。若有 N 个充实任务，耗时从基线的 N × 单次延迟压缩为约 max(N/32, 1) × 单次延迟。

除上述充实外，Opt 还在 main() 末尾初始化若干额外全局变量：child_force_killed=0（用于后续网络执行层的退出原因判断）、last_edges_count 和 edges_growth_rate（用于自适应阈值计算）、adaptive_plateau_threshold=UNINTERESTING_THRESHOLD=100（初始值，之后由运行时动态调整）。grammar-hypothesis 等重量级模块不在启动时加载，而是推迟到第一次 plateau 触发时按需初始化（延迟初始化），避免在前期探索顺畅阶段浪费资源。

第二阶段：种子选择与前沿加权

Opt 的评分公式在基线得分之上乘以一个"前沿加权因子"（frontier_bonus）。首先用 agnode(ipsm, sid_str, FALSE) 查询当前状态在 IPSM 图中是否存在及其出度：若状态不在图中（全新节点）或出度≤1，frontier_bonus=4.0；出度在 2-3 之间，frontier_bonus=2.0；出度≥4，frontier_bonus=1.0（不加权）。出度越低说明从该状态向外的转移路径越少，是最可能隐藏未发现转移的"探索前线"。

在出度加权基础上，每次评分时还会读取该状态的 error_hint 字段做可接受性修正：若 error_hint=1（服务器返回 4xx/5xx、尚未证明有探索价值），frontier_bonus × 0.25，将最高 4.0 倍的前沿奖励压低至普通已探索状态的水平；若 error_hint=0（响应类型未知，如二进制协议）且该状态已被选中 20 次以上但 productivity（= paths_discovered / (selected_times+1)）仍低于 0.01，frontier_bonus × 0.5；error_hint=2（已确认具有探索价值）不施加任何惩罚。最终 state->score = (u32)(base × frontier_bonus)。

error_hint 字段由 classify_state_error_hint() 在状态首次创建时依据响应码初始设定，并在每次 update_state_aware_variables()（即每次产生 interesting seed 时）动态修正：若某状态 error_hint=1 且已被选中≥10 次、productivity≥0.1，提升为 2（有价值，去除惩罚）；若 error_hint=0 且已被选中≥30 次、productivity<0.005，降级为 1（确认无价值，施加惩罚）。随着数据积累，调度权重自动向有价值的状态汇聚。

第三阶段：变异与执行（有界循环 + 退出原因自洽）

变异操作本身与基线相同。send_over_network() 中两个原本无界的循环均被改造：

覆盖率稳定性循环改为最多 500 次迭代的 busy-loop（stab_iter < 500），彻底消除 forking daemon 长尾覆盖带来的无限自旋。

进程终止等待循环改为有界轮询：先向 child_pid 发送 SIGTERM，然后每 200 µs 检查一次进程状态，最多等待 50 ms（250 次 × 200 µs）；若进程在 50 ms 内仍未退出，升级发送 SIGKILL 并设置 child_force_killed=1，再 usleep(1000) 等待内核清理后退出循环。

需要特别说明的是：发送 SIGKILL 是 Opt 自己新增的行为——基线的 send_over_network() 从不发送 SIGKILL。正是因为 Opt 引入了 SIGKILL 升级，才出现了一个新问题：run_target() 收到 SIGKILL 退出信号时，若不加区分，WIFSIGNALED && kill_signal==SIGKILL 在非 child_timed_out 情况下会走向 FAULT_CRASH 分支。child_force_killed 标志就是为了解决这个 Opt 自身引入的问题：当 run_target() 检测到 kill_signal == SIGKILL && child_force_killed 时，将结果改判为 FAULT_NONE，重置标志后继续——这是 Opt 内部的自洽设计，不涉及基线行为。

第四阶段：自适应停滞检测

Opt 不使用固定的停滞阈值。在 fuzz_one() 的 plateau triggering logic 块中，每 60 秒 wall-clock 时间（cur_ms - last_edges_check_time >= 60000）重新计算边增长率：edges_growth_rate = (agnedges(ipsm) - last_edges_count) / 时间差（分钟）。根据增长率动态设置 adaptive_plateau_threshold：增长率 > 5 边/分 → 阈值=150（探索顺畅，减少 LLM 干预）；1~5 边/分 → 阈值=100；≤1 边/分 → 阈值=50（基本停滞，加速 LLM 介入）。触发条件变为 uninteresting_times >= adaptive_plateau_threshold && chat_times < 64。

这个机制的核心逻辑是：LLM 调用有网络延迟代价，探索顺畅时让模糊测试器自主运行，停滞严重时快速求助。基线用 512 作为固定阈值，Opt 将此阈值变为可观测的 IPSM 边增长率的函数，实现了 LLM 调用时机的自适应控制。

第五阶段：状态感知的 LLM 介入

触发条件满足后，Opt 的流程与基线有根本性差异。

延迟初始化检查：若 hypothesis_ctx 为 NULL，在此时完成 grammar-hypothesis 系统的初始化，加载 RFC 知识库和假设适配器。

假设精炼门控：调用 periodic_hypothesis_refinement()，但内部有门控——仅当 hypothesis_validation_count % HYPOTHESIS_REFINEMENT_CHECK_INTERVAL（=5000）== 0 时才实际执行扫描。扫描逻辑：遍历所有假设，若某假设 fitness < 0.7 且已积累 3 个以上反例（counterexample），将反例附带到提示词中向 LLM 请求假设精炼，每次调用最多精炼一个假设，精炼结果重新集成到 IPSM 模式匹配。

状态上下文构造：若未开启消融模式（ablation_no_state_prompt=0），用 json-c 构建结构化 state_ctx JSON。全局字段：当前 IPSM 节点数/边数、edges_growth_rate、pending_favored、queued_paths、chat_times、target_state_id。状态字段：从所有状态中取 paths_discovered/(selected_times+1)（探索效率）最低的 8 个，每个状态含 id、paths、paths_discovered、selected_times、fuzzs、seeds_count、is_error（error_hint==1 时为 true）、productivity、seed_ids（最多 5 个可达种子的 queue index）。效率最低的状态排在最前，提示 LLM 重点关注这些"瓶颈"。

提示词哈希去重：用 djb2 对 examples+history+state_ctx 的拼接计算哈希，与最近 64 次调用的哈希环（LLM_DEDUP_SLOTS=64）比对。命中则增加 llm_dedup_hits 计数器并跳过本次调用，避免相同停滞上下文触发重复 LLM 请求。

fork 隔离调用：主进程 fork 一个子进程执行 LLM HTTP 请求。子进程根据路径选择：消融路径（ablation_no_state_prompt=1）调用 construct_prompt_stall_original() 生成简单提示词，temperature=1.2；正常路径调用 llm_handle_plateau(protocol_name, examples, history, state_ctx) 生成含拓扑信息的富提示词。子进程将结果写入 stall-interactions/llm-suggest-N，并将本次 token 用量写入同路径的 .tokens sidecar 文件。主进程 waitpid 等待，150 秒超时未返回则 SIGKILL 子进程继续运行——主循环在最坏情况下阻塞 150 秒，不会无限挂起。主进程读取 .tokens 文件累加 llm_total_prompt_tokens / llm_total_completion_tokens。

响应处理：用 validate_and_parse_llm_json() 做严格 JSON 模式验证。通过后：若返回 `suggested_request` 字段，提取后通过 common_fuzz_stuff() 执行；若返回 `actions[]`（仅正常路径），逐条处理——`set_target_state` 重定向全局 target_state_id；`prioritize_seeds` 将指定队列索引的种子标记为 favored，同时更新所有状态池中该种子的 selected_seed_index，确保状态重定向后仍能生效；`propose_mutations` 读取指定种子文件，依次执行 insert/replace/flip 操作生成变异副本，每个副本立即通过 common_fuzz_stuff() 提交执行；`suggest_strategy` 当前为 noop（保留扩展入口）。

Tier-1 假设采样验证：在 common_fuzz_stuff() 中，每 500 次执行（total_execs % HYPOTHESIS_VALIDATION_SAMPLE_RATE == 0）调用一次 validate_hypothesis_sampled()，复用 extract_requests() 已解析的 regions（零额外解析开销），对覆盖到的文法假设约束（正则、数值范围、枚举值）逐一检验，每 10 次失败收集一个反例更新 fitness，全程性能开销低于 0.01%。这与上方 Tier-2 的 plateau 精炼共同构成"文法充实→假设生成→连续采样验证→反例积累→plateau 精炼→假设更新"的完整闭环，而基线的文法充实只有启动时的单向输入、无反馈校正。

第六阶段：节点停滞检测

在 state_aware_mode 主循环的最外层（while(1) 之前），声明两个持久变量：prev_node_count_loop=agnnodes(ipsm)（初始节点数）和 node_stagnation_rounds=0（计数器）。在每轮种子选择的内层 while 循环中，比较 agnnodes(ipsm) 与 prev_node_count_loop：若节点数增长则更新 prev_node_count_loop 并重置 node_stagnation_rounds=0；否则递增计数器。当 node_stagnation_rounds > 80 且 UR(100) < 30（30% 概率），将本轮 effective_algo 临时覆盖为 RANDOM_SELECTION——完全随机选态，打破 FAVOR 算法可能导致的"热点锁定"。70% 的概率保留 FAVOR 算法主导地位，30% 的概率注入随机探索。这里的"停滞"是全局 IPSM 节点总量的停滞，与第四阶段的边增长率停滞是独立的两个维度：第四阶段感知边（状态转移路径）的发现速度，第六阶段感知节点（协议状态）的发现速度。

三、两者的本质区别与底层逻辑
基线的本质是"启动时充实 + 运行时盲目触发的单向翻译器"。它在启动阶段通过两次 LLM 批处理（文法获取 + 种子充实，串行阻塞）固化了协议知识，此后不再更新；运行时仅用一个固定计数器决定何时向 LLM 求助，用一个固定文本模板描述停滞、不携带任何 IPSM 拓扑信息，从 LLM 的自由文本响应中用正则提取消息序列后直接加入种子队列。整个运行时 LLM 通道是单向的：模糊测试器→LLM（固定模板），LLM→模糊测试器（自由文本），之后没有任何机制将建议效果反馈回下一次请求。

Opt 的本质是"并行启动充实 + 自适应状态感知的闭环协作器"。它将启动充实并行化（32 线程），将运行时停滞检测替换为基于 IPSM 边增长率的自适应阈值，在 LLM 触发时将完整的运行时拓扑状态（IPSM 节点/边数、每状态探索效率、growth_rate、seed_ids 等）编码为结构化 JSON 传递给 LLM，要求返回结构化操作指令，用严格 JSON 验证器校验，并将指令转化为三种直接作用于调度器的控制动作（状态重定向、种子优先级、精确变异）。除停滞时的状态感知介入外，还持续在每次执行后对文法假设做轻量采样验证，在 plateau 处理时周期性精炼低质量假设，形成完整的假设反馈闭环。

用控制论的框架来理解：

ChatAFL 基线是一个开环控制系统。控制信号（LLM 建议）的生成完全不依赖系统的实际输出（IPSM 拓扑、覆盖率、每状态探索效率）。阈值是预设常数，提示词是固定模板，响应解析是脆弱的正则匹配。如果 LLM 给出了低质量的建议，基线无从知晓，下次停滞时仍会发送同样的模板。

ChatAFL-Opt 是一个自适应闭环控制系统。它有三个可观测量：边增长率（宏观探索速度，60s 更新一次）、IPSM 拓扑（微观状态结构，随每次 update_state_aware_variables 更新）、每状态探索效率（局部饱和度，即 productivity，随每次 interesting seed 更新）。它有四个执行器：LLM 介入时机（自适应阈值 τ(t)）、状态选择权重（frontier_bonus 调度）、LLM 操作指令（set_target_state / prioritize_seeds / propose_mutations）、文法假设质量（Tier-1 验证 + Tier-2 精炼）。

控制律是自适应的：

  阈值 τ(t) 根据边增长率 Ė 动态调整：Ė > 5 → τ=150，1 < Ė ≤ 5 → τ=100，Ė ≤ 1 → τ=50

  前沿加权因子 β 根据出度调整：deg⁺=0/1 → β=4，deg⁺=2/3 → β=2，deg⁺≥4 → β=1；再根据可接受性修正：error_hint=1 → β×0.25，error_hint=0 且低生产率 → β×0.5，error_hint=2 → 无惩罚

  error_hint 本身随 productivity 数据动态更新：1→2（选中≥10次，productivity≥0.1），0→1（选中≥30次，productivity<0.005）

这种架构差异导致了实验中观察到的所有性能差异：

边覆盖率全面提升（10 个目标全胜，平均 +50.5%），根本原因是前沿加权机制将探索资源集中到低出度的边界状态——这些状态正是新转移边最可能被发现的位置。

节点覆盖率中等提升（6 胜 4 平，平均 +7.8%），因为状态感知的 LLM 建议能针对性地触达未知状态，比盲猜更有效。

代码覆盖率稳步提升（分支覆盖 7 胜，行覆盖 8 胜），因为更多状态转移意味着更多协议逻辑分支被执行。

初始发现速度显著加快，因为自适应阈值在停滞严重时（Ė≤1）将触发点压到 50，比基线固定的 512 快十倍。

吞吐量不受损，因为并行种子充实（32 线程）大幅缩短启动时间，有界循环消除了运行时无限阻塞风险，fork 隔离的 LLM 调用避免了主循环因网络故障无限挂起。
