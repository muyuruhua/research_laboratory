ChatAFL（基线）与 ChatAFL-Opt 的工作流、本质与底层逻辑

一、ChatAFL 基线的完整工作流

第一阶段：启动时 LLM 充实

main() 完成命令行解析、共享内存和 fork server 初始化、IPSM 图创建后，若检测到 -P 协议参数（protocol_selected），立即串行执行两个阻塞调用（L10696-10699），之后才调用 read_testcases()：

1. setup_llm_grammars()：对同一提示词执行 TEMPLATE_CONSISTENCY_COUNT=5 次迭代，每次迭代调用 chat_with_llm 两次（temperature=0.5，model=gpt-4o-mini）——一次获取主要消息类型模板，一次补充剩余模板——共 10 次 LLM 调用。各次结果通过一致性投票合并，只保留多数迭代中都出现的字段，生成 protocol_patterns 和 message_types_set。

2. enrich_testcases()：遍历 in_dir 中每个初始种子，检查缺少哪些已知消息类型，对每个"缺失组合"串行调用一次 enrich_sequence()（内部调用 chat_with_llm，temperature=0.5），要求 LLM 在现有请求序列中插入缺失消息类型并写回 enriched_N_filename 文件。整个过程串行、阻塞。

以上两阶段完成后才读取初始种子队列，协议知识从此固化，运行期间不再更新。关键常量：UNINTERESTING_THRESHOLD=512，CHATTING_THRESHOLD=64，STALL_RETRIES=2，GRAMMAR_RETRIES=5。

第二阶段：状态评分与种子选择

主循环每轮调用 choose_target_state(FAVOR)，内部执行 update_scores_and_select_next_state(FAVOR)（L828）对所有已知状态计算得分并做加权随机抽取：

  state->score = ceil(1000 × 2^(-log₁₀(log₁₀(fuzzs+1) × selected_times + 1)) × 2^(ln(paths_discovered+1)))

第一个指数项为负，fuzzs（变异次数）和 selected_times（被选次数）越大得分越低；第二个指数项正，paths_discovered 越大得分越高。公式完全不感知 IPSM 图的拓扑结构——出度为 0 的边界节点与出度为 10 的中心节点，在三个计数器相同时获得完全相同的调度优先级。前 5 轮（state_cycles<5）采用轮转（ROUND_ROBIN）以积累统计数据。

第三阶段：变异与执行

对选定种子施加比特翻转、算术运算、字典替换、拼接等标准 AFL 变异，然后通过 send_over_network()（L1290）将消息序列发送给目标服务器并采集覆盖率。

send_over_network() 末尾有两个真正的 while(1) 循环，均无上限：

  /* 覆盖率稳定性等待 */
  while (1) {
    if (has_new_bits(session_virgin_bits) != 2) break;
  }

  /* 进程消亡等待 */
  if (terminate_child && (child_pid > 0))
    kill(child_pid, SIGTERM);
  while (1) {
    int status = kill(child_pid, 0);
    if ((status != 0) && (errno == ESRCH)) break;
  }

对于 forking daemon（如 pure-ftpd），子进程的 ASAN 析构、fd 清理等操作持续产生新覆盖位，第一个循环会长时间自旋；若进程不响应 SIGTERM，第二个循环将永远不退出。send_over_network() 从不发送 SIGKILL——SIGKILL 只由 AFL 的 SIGALRM 超时处理器在 child_timed_out 置位时发出，在 run_target() 中走 FAULT_TMOUT 分支。

第四阶段：停滞检测与 LLM 介入

uninteresting_times 在每次 common_fuzz_stuff() 后更新：save_if_interesting() 返回真则重置为 0，否则递增。当 uninteresting_times >= 512 且 chat_times < 64 时（L6851），重置计数器并触发 LLM：

流程（L6852-7030）：读取当前种子的历史响应文件（responses-ipsm/id:...）→ 拼接 history 和 examples 字符串 → 调用 construct_prompt_stall(protocol_name, examples, history) 生成固定文本提示词（不含任何 IPSM 拓扑信息）→ 在主进程内直接调用 chat_with_llm(prompt, "gpt-4o-mini", 2, 1.5)（temperature=1.5，无 fork，无超时保护，主循环完全暂停）→ 返回的自由文本经 extract_stalled_message() 用正则提取消息序列 → 格式化后通过 common_fuzz_stuff() 执行 → chat_times++ → 保存到 stall-interactions/prompt-N 和 response-N。

本质：基线的 LLM 集成是"一次性启动充实 + 固定阈值触发的单向翻译器"。运行时 LLM 通道完全开环：提示词不携带 IPSM 拓扑，LLM 对当前有多少状态、哪些是边界、哪些从未被探索一无所知；LLM 建议的效果没有任何机制反馈到下一次请求。

二、ChatAFL-Opt 的完整工作流

第一阶段：并行启动充实 + 延迟初始化

启动时同样执行 setup_llm_grammars()（与基线相同，串行 5 次 × 2 次 LLM 调用）和 enrich_testcases()，之后调用 read_testcases()（L12132-12135）。区别在于：

enrich_testcases() 使用 pthread 线程池：先收集所有种子×消息类型组合形成任务列表，然后以 ENRICHMENT_THREADS=32 个工作线程并发执行所有 enrich_sequence() 调用，主线程 pthread_join 等待所有线程完成后统一写入结果（L3165-3182）。

main() 末尾额外初始化（L12245-12257）：child_force_killed=0、last_edges_count=agnedges(ipsm)、last_edges_check_time、edges_growth_rate=0.0、adaptive_plateau_threshold=UNINTERESTING_THRESHOLD=100。

Grammar-hypothesis 系统：Opt 在 main() 末尾只设置 hypothesis_mode=1，不执行 init_grammar_hypothesis_system()（L12168-12188）；实际初始化延迟到第一次 plateau 触发时（L7904-7908）。

四个消融开关（L504-507）由环境变量控制，用于隔离单项优化的贡献：CHATAFL_NO_FRONTIER、CHATAFL_NO_ADAPTIVE、CHATAFL_NO_REFINEMENT、CHATAFL_NO_STATE_PROMPT。

第二阶段：前沿加权状态评分

Opt 的 state_info_t 结构（aflnet.h）新增两个字段：error_hint（u8，0=未知、1=确认无效、2=确认有效）和 productivity（double，= paths_discovered / (selected_times+1)）。

update_scores_and_select_next_state() 在基线得分基础上乘以 frontier_bonus（L1017-1058）：

  /* 出度加权 */
  char sid_str[STATE_STR_LEN];
  snprintf(sid_str, STATE_STR_LEN, "%d", state_id);
  Agnode_t *nd = agnode(ipsm, sid_str, FALSE);
  if (nd) {
    int out_degree = 0;
    for (Agedge_t *e = agfstout(ipsm, nd); e; e = agnxtout(ipsm, e))
      out_degree++;
    if (out_degree <= 1)      frontier_bonus = 4.0;
    else if (out_degree <= 3) frontier_bonus = 2.0;
    /* else 1.0，不加权 */
  } else {
    frontier_bonus = 4.0;   /* 不在图中 → 最高前沿奖励 */
  }

  /* 可接受性惩罚 */
  if (state->error_hint == 1)
    frontier_bonus *= 0.25;
  else if (state->error_hint == 0 &&
           state->selected_times >= 20 &&
           state->productivity < 0.01)
    frontier_bonus *= 0.5;
  /* error_hint == 2：确认有效 → 无惩罚 */

  state->score = (u32)(base * frontier_bonus);

error_hint 在状态首次创建时由 classify_state_error_hint() 依据响应码设定（L1296-1334、L1444），并在每次 update_state_aware_variables()（即每次产生 interesting seed 时）动态修正（L1498-1537）：
- error_hint=1，selected_times≥10，productivity≥0.1 → 提升为 2（去除惩罚）
- error_hint=0，selected_times≥30，productivity<0.005 → 降级为 1（施加惩罚）

第三阶段：有界执行循环 + 退出原因自洽

变异操作与基线相同。send_over_network() 中两个无界循环均被改造（L1700-1756）：

覆盖率稳定循环：
  int stab_iter = 0;
  while (stab_iter++ < 500) {
    if (has_new_bits(session_virgin_bits) != 2) break;
  }
最多 500 次，彻底消除 forking daemon 长尾覆盖带来的无限自旋。

进程终止等待：
  child_force_killed = 0;
  kill(child_pid, SIGTERM);
  int kill_wait = 0;
  while (1) {
    if ((kill(child_pid, 0) != 0) && errno == ESRCH) break;
    if (++kill_wait >= 250) {          /* 250 × 200µs = 50ms */
      kill(child_pid, SIGKILL);
      child_force_killed = 1;
      usleep(1000); break;
    }
    usleep(200);
  }
先 SIGTERM，最多等待 50ms，若进程仍存活则升级 SIGKILL 并置 child_force_killed=1。

发送 SIGKILL 是 Opt 自身引入的新行为——基线从不发 SIGKILL。因此 Opt 需要在 run_target() 中自洽（L4456-4459）：
  if (kill_signal == SIGKILL && child_force_killed) {
    child_force_killed = 0;
    return FAULT_NONE;   /* 主动终止，非崩溃 */
  }
避免将自己发出的 SIGKILL 误判为 FAULT_CRASH。

第四阶段：自适应停滞检测

fuzz_one() 中每 60 秒 wall-clock 时间（L7858-7893）重新计算 IPSM 边增长率：

  edges_growth_rate = (agnedges(ipsm) - last_edges_count) / time_elapsed_min;

  if (edges_growth_rate > 5.0)       adaptive_plateau_threshold = 150;
  else if (edges_growth_rate > 1.0)  adaptive_plateau_threshold = 100;
  else                               adaptive_plateau_threshold = 50;

触发条件变为 uninteresting_times >= adaptive_plateau_threshold && chat_times < 64（L7895）。基线固定阈值 512；Opt 的阈值是 IPSM 边增长率的函数，范围 50-150，初始值 100。

第五阶段：状态感知的 LLM 介入

触发条件满足后（L7895 之后），Opt 的流程与基线有根本性差异：

延迟初始化检查：若 hypothesis_ctx==NULL，在此时调用 init_grammar_hypothesis_system()，加载 RFC 知识库、从 responses-ipsm/ 收集服务器响应样本、调用 LLM 生成文法假设并集成到 IPSM 模式匹配（L7904-7908）。

Tier-2 假设精炼（L7915-7916）：调用 periodic_hypothesis_refinement()，内部门控——仅当 hypothesis_validation_count % 5000 == 0 时才扫描。扫描逻辑：遍历所有假设，若某假设 fitness < FITNESS_THRESHOLD（=0.7）且已积累≥3 个反例，将反例附带到提示词中向 LLM 请求精炼，每次至多精炼一个假设，精炼结果重新集成到 IPSM 模式匹配。

提示词哈希去重（L8113-8135）：用 djb2 对 examples+history+state_ctx 的拼接计算哈希，与最近 LLM_DEDUP_SLOTS=64 次调用的哈希环比对，命中则跳过本次调用（goto plateau_done）。

状态上下文 JSON（L8044-8109）：若 ablation_no_state_prompt=0，用 json-c 构建 state_ctx，包含全局字段（nodes、edges、growth_rate、pending_favored、queued_paths、chat_times、target_state_id）和状态字段（按 paths_discovered/(selected_times+1) 升序排列的最差 8 个状态，每个含 id、paths、paths_discovered、selected_times、fuzzs、seeds_count、is_error、productivity、seed_ids）。

fork 隔离调用（L8137-8225）：主进程 fork 子进程执行 LLM 请求，子进程写结果到 llm-suggest-N 并写 token 用量到 .tokens sidecar；主进程 waitpid 最多等待 150 秒，超时则 SIGKILL 子进程。两条路径：
  - ablation_no_state_prompt=1：construct_prompt_stall_original() + chat_with_llm(temperature=1.2) + extract_stalled_message() 正则提取，结果包装为 {suggested_request:...} JSON
  - 默认：llm_handle_plateau(protocol_name, examples, history, state_ctx) 生成含拓扑信息的富提示词，直接返回 JSON

响应处理（L8262-8428）：validate_and_parse_llm_json() 做严格 JSON 模式验证，通过后：
  - suggested_request：提取字符串后通过 common_fuzz_stuff() 执行
  - actions[]（仅默认路径）：
    - set_target_state：校验 state_id 存在后重定向全局 target_state_id
    - prioritize_seeds：标记指定 queue index 的种子为 favored，并遍历所有状态池更新 selected_seed_index，确保状态重定向后 choose_seed 仍能命中
    - propose_mutations：读取指定种子文件，对每个 op（insert/replace/flip）生成变异副本并立即通过 common_fuzz_stuff() 执行，insert/replace 操作用 base64 编码字节，flip 操作指定位置和长度
    - suggest_strategy：noop（保留扩展入口）

Tier-1 假设采样验证（L7222-7229）：在 common_fuzz_stuff() 中，每 HYPOTHESIS_VALIDATION_SAMPLE_RATE=500 次执行调用一次 validate_hypothesis_sampled()，复用 extract_requests() 已解析的 regions（零额外解析开销），每次最多扫描 8 个 region，每 10 次验证失败收集一个反例更新 fitness。与 Tier-2 共同构成"假设生成→连续采样验证→反例积累→plateau 精炼→假设更新"的完整闭环。

第六阶段：节点停滞检测

state_aware_mode 主循环的外层（while(1) 之前，L12293-12315）声明两个持久变量：prev_node_count_loop=agnnodes(ipsm) 和 node_stagnation_rounds=0。每轮种子选择时检查 IPSM 节点数是否增长：增长则重置计数器；否则递增。当 node_stagnation_rounds > 80 且 UR(100) < 30（30% 概率）时，将本轮 effective_algo 临时覆盖为 RANDOM_SELECTION，打破 FAVOR 算法可能导致的热点锁定；70% 概率保留 FAVOR 主导地位。这里感知的是全局 IPSM 节点数停滞，与第四阶段的边增长率停滞是两个独立的观测维度。

三、两者的本质区别与底层逻辑

基线的本质是"一次性启动充实 + 运行时开环触发的单向翻译器"。启动阶段两次阻塞 LLM 批处理（文法获取+种子充实，串行）将协议知识固化到文件，之后不再更新；运行时以固定计数器阈值 512 决定触发时机，用固定文本模板描述停滞、不携带 IPSM 拓扑，在主进程同步阻塞等待 LLM 响应，从自由文本中用正则提取消息序列后直接加入队列。LLM 建议的效果没有任何通道反馈回下一次提问。

Opt 的本质是"并行启动充实 + 自适应状态感知的闭环协作器"。它将启动充实并行化（32 线程），将运行时停滞阈值替换为基于 IPSM 边增长率的自适应函数，在 LLM 触发时将完整运行时拓扑（节点/边数、各状态探索效率、growth_rate、seed_ids 等）编码为结构化 JSON 传给 LLM，要求返回结构化操作指令，经严格 JSON 验证后将指令转化为三种直接作用于调度器的控制动作；同时通过两级假设验证闭环持续修正协议文法知识；通过 frontier_bonus + error_hint 机制将调度权重偏向低出度边界状态并随运行数据动态修正。

用控制论框架理解：

基线是开环控制——控制信号（LLM 建议）的生成不依赖系统输出（IPSM 拓扑、覆盖率、每状态探索效率）。阈值是预设常数，提示词是固定模板，响应解析是脆弱的正则匹配。若 LLM 给出低质量建议，基线无从知晓，下次停滞时仍发送同样的模板。

Opt 是自适应闭环控制——三个可观测量（IPSM 边增长率 Ė、每状态 productivity、假设 fitness）驱动四个执行器（LLM 介入阈值 τ(t)、状态选择权重 frontier_bonus、LLM 操作指令、假设精炼）。控制律：

  阈值 τ(t)：Ė > 5 → τ=150；1 < Ė ≤ 5 → τ=100；Ė ≤ 1 → τ=50

  frontier_bonus β：deg⁺=0/1 → β=4；deg⁺=2/3 → β=2；deg⁺≥4 → β=1；
    再乘 error_hint 惩罚：error_hint=1 → β×0.25；error_hint=0 且低生产率 → β×0.5；error_hint=2 → 无惩罚

  error_hint 本身随 productivity 动态更新：1→2（selected≥10，productivity≥0.1）；0→1（selected≥30，productivity<0.005）

  假设 fitness 随 Tier-1 采样验证持续更新，Tier-2 在每 5000 次验证后精炼低质量假设（fitness<0.7 且 counterexamples≥3）

这种架构差异从机制层面决定了两者的本质能力差距：前沿加权将探索资源集中到低出度边界状态；自适应阈值在停滞严重时主动加快 LLM 介入；状态感知的结构化提示使 LLM 能针对性地触达未探索区域；有界循环消除运行时无限阻塞风险；fork 隔离避免主循环因网络故障挂起；假设闭环使协议知识随运行持续修正而非启动后固化不变。
