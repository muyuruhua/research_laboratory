# 问题诊断与解决方案

## 一、问题描述

您执行了 `./run.sh 5 10 kamailio chatafl` 命令，容器运行了 58 分钟仍无结果。

## 二、根本原因分析

### 🔴 核心问题：setup.sh 未执行

通过诊断发现以下关键问题：

1. **❌ KEY 环境变量未设置**
   ```bash
   $ echo $KEY
   (空输出)
   ```

2. **❌ 源代码未复制到 benchmark 目录**
   ```bash
   $ ls benchmark/subjects/SIP/Kamailio/
   # 只看到：Dockerfile, README.md, run.sh 等
   # 缺少：chatafl/, chatafl-cl1/, chatafl-cl2/, chatafl-enhanced/
   ```

3. **❌ Docker 镜像内没有编译好的 fuzzer**
   ```bash
   $ docker exec <容器ID> ls /home/ubuntu/kamailio/chatafl/
   ls: cannot access '/home/ubuntu/kamailio/chatafl/': No such file or directory
   ```

4. **⚠️ 容器内大量错误**
   ```
   Could not open output file 'dua_buffer_alloc.c.gcov'
   Could not open output file 'dua_error_throw.c.gcov'
   ... (数十个类似错误)
   ```

### 问题链条

```
未设置 KEY → setup.sh 未执行 → 源码未复制 → Docker 构建失败 → fuzzer 无法运行 → 容器空转 58 分钟
```

## 三、完整解决方案

### 步骤 1：清理现有容器（✅ 已完成）

```bash
# 停止并删除所有容器
docker stop $(docker ps -aq)
docker rm $(docker ps -aq)
```

### 步骤 2：设置 OpenAI API 密钥

```bash
# 设置 API 密钥（请替换为您的真实密钥）
export KEY="sk-your-openai-api-key-here"

# 验证设置成功
echo $KEY
# 应该输出：sk-your-openai-api-key-here
```

### 步骤 3：执行 setup.sh

```bash
# 运行 setup.sh 进行环境配置
./setup.sh
```

**setup.sh 会完成以下操作**：
1. ✅ 更新所有版本的 API 密钥到 `chat-llm.h`
2. ✅ 复制源码到 benchmark 目录：
   - `ChatAFL` → `benchmark/subjects/*/chatafl/`
   - `ChatAFL-CL1` → `benchmark/subjects/*/chatafl-cl1/`
   - `ChatAFL-CL2` → `benchmark/subjects/*/chatafl-cl2/`
   - `ChatAFL-Enhanced` → `benchmark/subjects/*/chatafl-enhanced/`
3. ✅ 自动触发 Docker 镜像重新构建

### 步骤 4：验证 setup 成功

```bash
# 检查源码是否复制成功
ls benchmark/subjects/SIP/Kamailio/
# 应该看到：chatafl  chatafl-cl1  chatafl-cl2  chatafl-enhanced  Dockerfile ...

# 检查 API 密钥是否更新
grep "OPENAI_TOKEN" ChatAFL/chat-llm.h
# 应该看到您的 API 密钥
```

### 步骤 5：重新运行模糊测试

```bash
# 选项 A：运行 ChatAFL
./run.sh 5 10 kamailio chatafl

# 选项 B：运行 ChatAFL-Enhanced
./run.sh 5 10 kamailio chatafl-enhanced
```

## 四、参数说明

```bash
./run.sh <容器数> <超时分钟> <目标> <fuzzer类型>
```

| 参数 | 说明 | 示例值 |
|------|------|--------|
| 容器数 | 并行运行的 Docker 容器数量 | 5 |
| 超时分钟 | 每个容器的模糊测试时长（分钟） | 10 |
| 目标 | 要测试的目标程序 | kamailio |
| fuzzer类型 | 使用的 fuzzer 版本 | chatafl / chatafl-enhanced |

**注意**：
- ⏱️ 超时时间 = 10 分钟 → 每个容器会运行 **600 秒**
- 🐳 容器数 = 5 → 会启动 **5 个并行实例**
- 📊 总计算时间 = 超时时间（不是 超时×容器数，因为是并行）

## 五、常见超时原因

### 为什么容器运行了 58 分钟仍未停止？

1. **fuzzer 未启动** → 容器一直等待超时（本次问题）
2. **超时配置错误** → run.sh 内部的 TIMEOUT 计算有问题
3. **Docker 等待逻辑** → `docker wait` 命令未正确触发

### 检查容器实际运行状态

```bash
# 查看容器日志
docker logs <容器ID> 2>&1 | tail -100

# 查看 fuzzer 进程
docker exec <容器ID> ps aux | grep afl-fuzz

# 查看 fuzzer 统计信息
docker exec <容器ID> cat /home/ubuntu/experiments/*/chatafl/out*/fuzzer_stats
```
