# 从 forked-daapd 漏洞泛化：构造新漏洞种子/种子序列的方法论

日期：2026-09-25。

## 1. 解剖：那个漏洞为什么能被构造出来

SMARTPL 死锁的结构要素：**嵌入式子解析器**（URL 查询参数里的表达式语言）× **词法层毒输入**
（0x81 高位字节 + 裸 `?` + 28 长同质游程）× **无界错误恢复**（ANTLRv3 递归不返回）×
**事件循环架构**（单请求即全局 DoS）。四个要素里只有第一个是"选择目标"的要素，
后三个都是**可枚举的毒素类**——这就是可泛化性的来源。

## 2. 五步构造法

1. **盘点子解析器**：主协议语法之下还解析"第二种语言"的入口——查询/过滤表达式、
   地址文法、头部值文法（Range/ETag/日期/引号串）、glob 模式、Sieve/播放列表脚本。
   这些代码上游测试覆盖最少、多为生成代码或弱错误恢复的手写递归下降。
2. **选毒素维度**（六类，前四类已有算子，后两类无）：

   | 毒素 | 形态 | 算子 |
   |---|---|---|
   | 词法歧义 | 高位字节 + 值中裸定界符 | S12（**仅 URI 域**） |
   | 深度游程 | 长同质串压垮有界前瞻 | S12（同上） |
   | 转义失配 | `\X` 消费 2 存 1 | S2c/S11 |
   | 数值饱和 | 长度/计数字段打边界 | S1 |
   | **嵌套失衡** | 深层不配对引号/括号 → 递归栈溢出类 | **缺（S13 候选）** |
   | **集合洪泛** | 列表型值的海量元素（多区间/多参数/多地址） | **缺（S14 候选）** |

3. **序列模板**：`[协议握手到达子解析器] + [合法子语言前缀进入解析状态] + [类毒素] + [可选重复/并行]`。
   forked-daapd 单请求即中是因为 worker=事件循环；线程/进程 per-conn 的目标需要序列或并发。
4. **验收**：崩溃或属性违例 + 确定性 ×3（SEED-LIBRARY 口径）。
5. **命中后算子化回灌 loopfuzz**。

## 4. loopfuzz 算子缺口图（新漏洞搜索面的下一步）

1. **S13 嵌套失衡**：对引号/括号跨度做重复注入（`\"`×N、`(((`×N）——栈溢出/递归类；
2. **S14 集合洪泛**：对列表型头部值（Range/参数表/地址表）做元素倍增；
3. **S12 扩域**：从 URI 域扩展到头部值域（mode="..."、显示名、地址 local-part）——
   exim 250-接受线索表明毒输入能进入深层解析，扩域后可能命中。

## 5. 结论

方法论本身可复用：**子解析器 × 毒素矩阵 × 序列模板**就是新漏洞种子的构造空间。本轮对
exim/lighttpd/live555 的 28 个新形态实测全部未命中——与六层漏斗一致（成熟快照的在窗
漏洞稀缺）；两个有价值产出：(a) exim 接受 lexer-kill 地址的深挖线索，(b) 三个算子缺口
（S13/S14/S12 扩域）构成下一轮搜索面。
